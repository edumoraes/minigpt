# MiniGPT — AGENTS.md

Minimal GPT implementation from scratch in Portuguese, for learning. Trains on a synthetic Portuguese corpus generated by `data/corpus.py`, not real data.

## Commands

```bash
python main.py train    # Pre-training (saves to output/)
python main.py sft      # Supervised fine-tuning on output/melhor_modelo.pt
python main.py dpo      # Preference optimization (uses the SFT model if present)
python main.py sample   # Batch generation with the most advanced model available
python main.py chat     # Interactive chat (needs a TTY)
python main.py info     # Inspect a saved checkpoint
```

`train` must run before the others. It accepts overrides: `--epochs`, `--batch_size`, `--context_len`, `--d_model`, `--n_layers`, `--accum`, `--tokenizer {bpe,char}`, `--no-rope`, `--corpus FILE`.

## Training on Colab

Training is meant to run on a Colab GPU through the colab CLI (`uv tool install google-colab-cli`, then `colab whoami` to log in):

```bash
python colab_train.py                                     # train → sft → dpo → sample on a T4
python colab_train.py --etapas "train --epochs 3" sample  # stages are main.py commands
python colab_train.py --cpu --etapas "train --epochs 1"   # cheap smoke test
python colab_train.py --manter                            # keep the VM: colab console -s minigpt
```

`colab_train.py` (stdlib only) packs the working tree (tracked + untracked-but-not-ignored files, uncommitted changes included), uploads it to a new VM, runs the stages in the background while polling `treino.log`, downloads `output/` into the local `output/` (previous files go to `output/anterior-<date>/`), and stops the VM on success, on error and on Ctrl+C. It refuses to start if a session with the same name exists, since `colab new` would orphan it. A VM spends compute units while it is on: check `colab usage` and `colab sessions`.

Cost: an epoch covers every sliding window of `context_len` tokens over ~413k tokens (the train split plus two augmented copies), ~12.9k batches at batch_size 32. That can take several minutes per epoch on a T4; `train` prints throughput and an upper-bound ETA every 30 s.

## Architecture

| File | Role |
|------|------|
| `main.py` | CLI entrypoint (argparse subcommands) |
| `config.py` | All hyperparams in `GPTConfig` dataclass |
| `model.py` | GPT from scratch: LayerNorm, attention with RoPE + `F.scaled_dot_product_attention`, FeedForward, TransformerBlock, GPTModel |
| `train.py` | Pre-training: train/val split, augmentation, warmup + cosine LR over the planned steps, early stopping, checkpoints |
| `sft.py` | Supervised fine-tuning: loss only on response tokens, targets end in `<EOS>` |
| `dpo.py` | Direct Preference Optimization against a frozen copy of the model |
| `generate.py` | Sampling (temperature, top-k, top-p, repetition penalty, typical) and beam search |
| `tokenizer.py` | `BPETokenizer` (default, vocab 500) and `CharTokenizer` |
| `data/corpus.py` | Synthetic corpus generator, augmentation, SFT/DPO pairs |
| `colab_train.py` | Runs the stages on a Colab VM |

- **The corpus is generated on every run** (`carregar_corpus()` calls `gerar_corpus()`, deterministic with seed 42, ~10 ms). There is no cached file; edit `data/corpus.py` to change the data.
- **The validation split happens before augmentation**: the permuted and char-dropout copies come only from the train part. About 11% of val sentences still appear in train because the corpus repeats sentences.
- **Tokenizer**: BPE pre-tokenizes on whitespace, so merges never cross word boundaries; the vocab comes from the corpus. Special tokens `<PAD> <UNK> <BOS> <EOS>` are always ids 0–3 (`EOS_ID` in `tokenizer.py`). Characters absent from the corpus (`I`, `É`) become `<UNK>` and vanish when decoding, which is why "Instrução" prints as "nstrução".
- **SFT/DPO targets end in `<EOS>`** so the model learns to stop; generation stops at `<EOS>`. SFT masks the instruction targets but keeps the one that predicts the first response token.
- **Model uses weight tying** (`lm_head.weight` is `token_embedding.weight`) and **pre-norm** blocks.
- **Checkpoint keys**: `modelo`, `config` (a pickled `GPTConfig`, hence `weights_only=False`), `epoch`, `loss`, plus `val_loss`, `total_tokens`, `tempo_total_seg` for pre-training or `tipo` (`sft`/`dpo`) for fine-tuning.

## Key Constraints

- `d_model` must be divisible by `n_heads` (asserted at runtime).
- `context_len` must match between training and inference; the RoPE cache only covers `context_len` positions.
- SFT/DPO samples longer than `context_len` are skipped.
- SFT/DPO defaults barely move the model: 20 SFT pairs and 10 DPO pairs fit in one batch, so it is one optimizer step per epoch (5 steps at lr 1e-5 for SFT, 3 at 1e-6 for DPO). Raise `sft --epochs/--lr` to experiment.
- Output dir `output/` and `*.pt` files are gitignored.
- All code comments and strings are in Portuguese.
- Auto-detects device: CUDA → MPS → CPU.
